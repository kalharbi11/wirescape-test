# fx.reverb: design and provenance

**Original code**, GPL-3.0-only. No third-party source code or Clouds/Mutable Instruments code is copied.

The network uses the classic lossless feedback-delay-network construction and Schroeder input allpasses. Textbook references:
- Jot and Chaigne, *Digital Delay Networks for Designing Artificial Reverberators*, AES 1991: lossless feedback mixing, line-dependent damping and time constants.
- Stautner and Puckette, *Designing Multi-Channel Reverberators*, Computer Music Journal 6(1), 1982: multichannel delay-network mixing.
- Schroeder, *Natural Sounding Artificial Reverberation*, Journal of the AES 10(3), 1962: allpass diffusion.

## Topology and decisions

Eight mutually distinct prime lengths (48 kHz bases: 1499, 1741, 1999, 2281, 2617, 3011, 3469, 4789 samples) are recalculated for the rate and `size` every 64 absolute samples. A 50 ms one-pole glide plus fractional linear taps avoids discontinuous jumps. At size 1 the longest line is ~100 ms. The orthonormal 8×8 normalized Hadamard butterfly preserves energy when frozen. The normal-feedback coefficient per line is `exp(-ln(1000) × line_samples / (rate × RT60))`, so *amplitude* falls by 60 dB over RT60 irrespective of size. One-pole feedback damping is removed in freeze.

Two allpass sections per input side and separate up-to-250 ms predelays precede alternate-line excitation. Input is attenuated as freeze approaches, the feedback gain approaches 1 over 20 ms, and motion is likewise suspended. Two fixed-phase, slow sine LFOs modulate the fractional taps deterministically. The two wet projections are orthogonal before optional mid/side width collapse. Wet/dry gains use cosine/sine equal power; at Mix=0 output bypasses the math to preserve exact dry bits. A conservative ±8 internal safety ceiling and ±2 final output ceiling are present only for pathological signal levels.

Line, predelay and allpass memory uses `WS2_LARGE` allocated in `prepare`; no state allocation, I/O, locks, exceptions, or random seed in the callback. State only contains a version word: loading it resets the delay buffers intentionally, rather than promising audio-tail continuation.

**Listening note:** No physical-audio listening was performed by the builder. Review room-to-hall colour, stereo width at fully wet, and freeze on/off transitions after a sustained chord on the owner device.

## S7.1 correction 2/2: unchanged internal 48 kHz clock

The original non-48 kHz prime re-rounding changed room geometry. Correction 1 fixed the physical-time lengths but empirically scaled damping by `pow(48000 / rate, .75)`, fitting the default damping=0.4 row only. Architect A13 verified its high-severity regressions at 0.7 and 0.9. This multiplier changed damping colour. The 96 kHz network also applies twice the number of feedback-filter iterations per physical second and excites a different Nyquist band. The 96 kHz suffix-envelope mismatch is not simply a pole-time-constant conversion: matching the pole alone also failed.

Correction 2/2 **removes all damping rate calibration**: for non-48 kHz host rates the tank is processed on the original 48 kHz clock. Eight delay lines, their feedback filter, four allpass diffusers, predelay and LFO advance at exactly 48k. A scalar phase accumulator maps each host sample to zero, one or more tank ticks; the current host input and parameter values are held across those internal ticks. The latest wet tank sample is held between ticks. Dry signal, Mix and Width remain processed at every host sample. A zero-Mix signal therefore bypasses the tank and retains exact dry PCM. All persistent storage comes from host allocations in `prepare`; callback processing allocates nothing.

At **exactly 48 kHz**, the existing sample loop is taken directly, preserving the old 48 kHz arithmetic and output path, along with module IDs, port order, parameter/state versions and freeze semantics. A local standalone C++ reproduction matched the Architect's old four-setting numerical values and predicted less than 0.03% R2 spread for damping=0.1/0.4/0.7/0.9 with the fixed internal clock. This is **diagnostic only**; actual hosted base/head values and CI must establish acceptance. The original default <=5% folder assertion is unchanged; the same metric now reports 0.1, 0.7 and 0.9 with a stronger 1% guard at size 0.5 and default decay.

**Review trade-off:** sample-held wet reconstruction can introduce spectral images/droop at higher host rates; freeze and motion are quantized to the tank's original 48k tick, while dry, Mix and Width retain host-rate resolution. This is explicit and not claimed as a separate wideband sound-quality acceptance. D5/production R2 from #193 pinned to `8823c78` is **stale for the new source**. New source-pinned R2 and D5 evidence, 48k Golden x3, instruction cap, Cortex-M7, independent reviewer approval and durable release publication remain outstanding; S7.2 has not started.

## S7.2: headroom, continuous dry limit and transparent smooth knee (correction 2/2)

The exact-head initial S7.2 proposal (`0025eab9`) lowered wet makeup to 3.8 and applied 0.90 headroom. The first automatic [Lab 44452687090](https://github.com/kalharbi11/wirescape-lab/actions/runs/44452687090) failed the **unchanged** full-wet-versus-dry assertion on x64, ARM64, Windows and sanitizers at -7.95 dB versus the existing +/-6 dB requirement. The [Golden 44452687461](https://github.com/kalharbi11/wirescape-lab/actions/runs/44452687461) diagnostic ZIP verified the 17 declared Reverb bundles and 10 unlisted byte-identical outputs; the initial change also reduced `scene-01-hollow-chapel.json` RMS -1.7583 dB, exceeding the +/-1.5 dB criterion. Those failures are retained, not excused or deleted.

The correction restores the original `kWetMakeup=5` to retain full-wet loudness. For Mix >= 0.3, the established mixed-output headroom `0.88+0.04*mix` is unchanged (0.892 at module default Mix 0.3; 0.92 at full wet). Independent review [7020636057](https://github.com/kalharbi11/wirescape-lab/pull/255#issuecomment-7020636057) discovered that this old factor applied to every Mix > 0, while the exact-zero branch returned unity: this created a discontinuous ~1.11 dB dry level step under Mix modulation. Ordinary correction 2/2 retains the same gain at and above 0.3, and smoothly blends the headroom to exact unity as Mix approaches zero using `t=mix/0.3`, `smoothstep=t*t*(3-2*t)`, and `1+smoothstep*(old_gain-1)`. The blend and its first derivative are continuous at both endpoints; at Mix=0 the exact dry bypass remains bit-identical on both the native 48 kHz and off-rate host paths. This does not guarantee unchanged RMS for patches with nonzero Mix below 0.3 or automated through it; new-head Golden must measure them. An extremely loud coherent full-scale noise stimulus can nevertheless produce >2 FS peaks before the old safety guard at Mix 1 / Decay 20; simply increasing static attenuation enough to eliminate these would violate the full-wet loudness assertion. A zero-latency **transparent soft knee**, linear through 1.25 FS, then continuously slope-matched with `1.25 + 0.5*excess/(0.5+excess)`, asymptotically limits peaks below 1.75 FS *before* the preserved +/-2 fault-safety guard. The knee is explicitly a nonlinear gain-stage for extreme inputs, not disguised clamp removal, retuned feedback, or a zero-sound-change claim.

The test-only meter exposes raw mixed peak **before the new knee**, final pre-hard-clamp peak, soft-knee sample count and any hard-clamp hits. New full-scale 8 s correlated/antiphase tests require a nonzero soft-knee count, bounded pre-hard-clamp peak <2 and **zero** +/-2 hard-clamp hits; the default full-scale 440 Hz test must remain ≤1 FS with no knee use. No extra allocation, state, SDK, parameter, port or host-rate adapter change. All S7.1 rate/damping/freeze/RT assertions stay intact. The knee leaves ordinary levels linear, but the restored dry-limit gain curve changes some low-Mix outputs: exact-source hosted Golden must establish every bundled patch RMS and unlisted hash without assumptions.

The previous correction's raw/soft-knee numerical diagnostics were from an unpinned standalone simulation, not a production run; no such unverified numerical values are used as acceptance evidence. The hosted [old-source Lab 44486830182](https://github.com/kalharbi11/wirescape-lab/actions/runs/44486830182) passed the meter assertions, while the [matched full-mode MO run 44517989583](https://github.com/kalharbi11/wirescape-lab/actions/runs/44517989583) and [old-source D5 publication](https://github.com/kalharbi11/wirescape-lab/pull/255#issuecomment-7008187061) remain pinned to `137a6abe` versus `f314b859`. This **new** source correction adds a folder regression that moves Mix across zero at 44.1, 48 and 96 kHz; it preserves the Mix=0 exact-dry assertion and requires near-zero output to approach dry within 0.0005 FS on both channels. The original full-scale/no-hard-clamp, loudness, damping, state and RT tests remain intact. **Fresh** hosted Lab/Golden with per-patch RMS, x64/ARM64 Ir, matched full-mode production MO and separately rendered/published D5 are required at the next exact source head. Prior success cannot certify changed Reverb bytes. Correction ledger is 2/2; any further ordinary source change requires SR6 disposition.


## MOD-9 — Freeze stepped modulation audit

Workshop override starts from a byte copy at lab commit `3d3db7a64090682a62f220d73baef49709048c87` (LAB_PIN). Original code, no additional external source. Only production change is adding `WS2_MODULATABLE` to the existing `WS2_STEPPED | WS2_AUTOMATABLE` flags on slot 6 (`freeze`).

| Effective read site | Cadence and decision |
|---|---|
| `process`, native 48 kHz | Reads `b.param(FREEZE).value(0, i)` per host sample, threshold >= 0.5. Existing scalar `freeze_amount` slews toward 0/1 by 1/960 per tank tick. |
| `process_core_sample`, non-48 kHz | Same effective channel-0 read per internal tank tick; adapter holds current host row sample over zero or more 48 kHz ticks. The existing phase accumulator and sample counter determine the cadence, independent of host block size. |

Both paths derive input drive, motion, damping and feedback from `freeze_amount` without reallocating, changing topology, re-priming delay lengths, or clearing history. Freeze is therefore realtime-safe for stepped modulation, including release; no other parameter is changed. The existing parameter order, ranges, defaults, ports, state version and host-rate adapter remain untouched.

All delay/predelay/diffuser storage is obtained through `Setup::alloc(..., WS2_LARGE)` in prepare. Process and reset use existing fixed arrays/scalars and preallocated history, no allocation, locks, I/O, exceptions or logging. Persistent double fields are `core_phase` (host-to-tank timing accumulator) and `delay[8]` (fractional tap glides; float would stall before integer targets). No new state. Version 1 state is a version word, with host-owned parameter restoration and reset of history on load.

Tests: exact stepped and continuous flags, legacy IDs; effective nonconstant rows at 44.1, 48 and 96 kHz with an independent 48 kHz tick/drive oracle, including threshold and release. Registered ABI callback comparisons against single-host-sample constant rows, 1/16-channel host contexts (WS2_SUM supplies a mono row per input), difference from unfrozen audio, finite and bounded outputs, allocation watch and reset/state-v1 equivalence. Existing freeze retention, damping, gain staging, rate and block regression tests retained. Default-tail offline demo exercises the pinned default parameters.
