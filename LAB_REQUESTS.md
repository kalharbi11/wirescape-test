# Lab requests (living ledger)

Lab-facing gaps found while building modules here (AGENTS.md rule 2). One row per gap. **Nothing is filed
in `kalharbi11/wirescape-lab` unless the owner asks** (owner, 2026-11-27); then file the issue, label it
`limitation found`, and set the row to `sent to lab #N`.

- Check this table before adding a row; reuse a row when another module hits the same gap.
- IDs are never reused or renumbered. Add rows at the bottom.
- Each module's `DESIGN.md` "Limitations" links to its rows. A module that needs a lab behaviour change is
  `blocked: LR-n` in `modules/README.md`.
- Status: `open`, `sent to lab #N`, or `done` (the lab fix is in the pinned lab; keep the row).
